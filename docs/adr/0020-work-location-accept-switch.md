# 自动接受工作地点用平台开关，不新增值守规则动作

## Status

accepted（2026-11-09；Boss 侧已实现，智联留空实现）

## Context

Boss 的 HR 会在会话里发一张「您是否接受此工作地点?」的卡片，带「暂不考虑」「可以接受」两个按钮。当前 `readMessages` 把它当普通文本读成整块正文（标题、地址与按钮字），值守拿这段文本去判定：既命中不了任何规则，也不会点按钮 —— 表现为 AI 回一句不相干的话。

需求是：识别到这张卡片就点「可以接受」；识别范围是整个消息区，触发范围只限有红点的会话；点完不另发文字（卡片后面还有对方消息时才照常按那条消息回复）；默认不生效。

## Decision

1. **用每平台一份、默认关的开关**（`platform_config.work_location_accept_enabled`，V21），不用 `reply_rule.action` 新取值。理由：`ReplyRuleEngine.decide()` 是「最后一条消息的文本命中关键词才动作」，而这次是「在整个消息区里按页面结构认出一张卡片」，两者入口不同；硬套规则动作得给卡片正文配关键词，而且只能作用于最后一条消息。「默认不生效」也只有平台开关那一套能做到四处写法一致：列默认值 0、`ConfigStore.defaults()` 设 0、读侧 null 按关、前端初始 false。
2. **读侧判据只有一处**：`UnreadWatcher.sweep()` 读一次开关，把答案传给三条路径。演练路径靠 `ChatMessage.workLocationCard` 标记预演，不调用任何会点按钮的方法。
3. `PlatformAdapter.acceptWorkLocation` 由 Boss 实现、智联返回 `UNSUPPORTED`（还没在这边遇到过这类卡片，没有可依据的页面结构）。编排层不按平台分支。
4. **一轮最多点一张**：取页面顺序上最后一张卡片；按钮「不再可点」是唯一成功凭据 —— 点击前与点击后共用同一个判据，不必猜平台把按钮改成消失、变灰还是换文案。
5. 成功写一条 `reply_log`（`ACCEPT_WORK_LOCATION`，来源 `LOCATION`），复用 `wasProcessed` 挡住重复处理；不复用 `REPLY_RESUME`，否则「值守发简历数」会被算进去（ADR-0004）。点击未确认记运行日志提醒，不排重试。
6. 卡片是最后一条时跳过整个回复流程；否则照常把最后一条消息交给规则与 AI。
7. **按钮不可点是「这张卡片已经接受过」的终态**，不是失败：不写 `reply_log`、不记 WARN、不排重试，只记一条说明。是否跳过回复仍由卡片在页面上的真实位置决定，不能在这里写死。

## 真实点击后的页面状态（2026-11-09 补充）

用户手动点了一次「可以接受」，随后用只读方式取回同一会话的页面结构，得到：

| 观察点 | 结果 |
|---|---|
| 两个按钮 | 都从 `btn-v2 btn-*-v2` 变成 `btn-v2 disabled btn-*-v2`，文案仍是「暂不考虑」「可以接受」，没有消失 |
| 成功判据 | `disabled` 正好是 `BossSelectors.WORK_LOCATION_DISABLED_CLASS`，`hasClass` 按类名精确分词比对，判据成立，无需改动 |
| 新增消息 | 平台自动代发一条 `li.message-item.item-myself`，`data-mid=405808636858883`，正文「工作地点我可以接受。」，带「送达」状态 |
| 我方消息识别 | `item-myself` 与 `BossSelectors.MESSAGE_SELF_CLASS` 一致，不会被误读成对方的话 |
| 消息区顺序 | 卡片不再是最后一条；会话列表摘要也变成「工作地点我可以接受。」 |
| 列表容器 | `<ul class="im-list">` 在 `<div class="chat-message">` 内，与 `MESSAGE_ITEM` 选择器匹配 |

由此修掉一处缺陷：`WorkLocationResult.notClickable()` 原先写死 `cardIsLast=true`。卡片点过之后按钮常灰、且平台代发消息使它不再是最后一条，这个写死值会让 `blocksReply()` 恒为真，**对方之后在这个会话里说的每句话都会被值守跳过**。现在按页面真实顺序传值，并让 `readMessages` 只把「按钮仍可点」的卡片标成待接受 —— 否则演练会对着一张已接受过的卡片报「本会接受工作地点」。

## Considered Options

- **新增一个规则动作取值**（照 `SEND_RESUME` 抄）：改动更少，但要求关键词命中、只作用于最后一条消息，与「整个消息区识别」冲突；而且 `V3` 种子规则加 `V10` 使全新安装自带一条已启用的 `SEND_RESUME` 规则，那套机制本身就不是「默认关」。
- **把点击塞进 `readMessages`**：读消息产生副作用会捅破演练模式「方法体里没有外发动作」的结构性保证。
- **只在 `BossAdapter` 加方法、编排层按平台分支**：把平台判断散进编排层，与 ADR-0003 的分工相反。

## Consequences

- 只对有红点的会话生效：用户手动点开看过、红点清掉的会话不会被自动点到。这是刻意的边界。
- 成功凭据「按钮不再可点」已于 2026-11-09 用一次真实点击验证：平台加的是 `disabled` 类，正好落在已有判据里。点击后的类名与文案仍写进运行日志，用于日后改版时校正。
- 平台会自己代发一条我方文字消息，因此「卡片是最后一条」只在点击那一刻成立。编排层必须按页面真实顺序传值，不能把「按钮已灰」等同于「卡片还在末尾」。
- 智联侧留了契约位置但没有识别逻辑；真遇到同类卡片时补一个实现即可，不需要改编排层。
