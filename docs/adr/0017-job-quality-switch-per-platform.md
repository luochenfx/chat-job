# 岗位质量判断按平台开关，默认关

## Status

accepted（2026-11-05）。落在 `platform_config.job_quality_enabled`（V20）与控制台「平台配置」页。

## Context

岗位质量判断（ADR-0015）上线时没有自己的开关：它挂在值守的 AI 路径上，要停只能连
「AI 自动回复」一起关掉。只想要自动回复、不想为每段会话多花一次模型调用的人，没有第三条路。

## Decision

1. **每平台一份。** 判断本来就是按平台跑的：每日上限按平台计数、会话按平台归属，
   「Boss 开、智联关」是正常用法。判断点与分数线这类「我的标准」仍留在 `ai_config`，
   两个平台共用，不跟着搬 —— 它们是人的偏好，不随平台变。

2. **默认关。** 这是一个会安静花钱、安静发消息的功能：开着的人每聊起来一段会话就多一次
   模型调用，关着的人付出零。默认开等于让所有升级上来的人在没同意的情况下继续付费；
   默认关只等于有人要多点一次开关。

3. **迁移把已有行也改成关。** `ALTER TABLE ... ADD COLUMN ... DEFAULT 0` 会让升级上来的库
   一起变 0。另一条路（加列后再 `UPDATE` 回 1）会让「默认值」在库里有两种含义，
   而真正会被观察到的对象正是已有安装。

4. **只停判断，不停处置。** 关掉之后不调模型、不写评估、不发提醒；已经写下的评估、
   「重点关注」页、人工接管全部照常。要停的是花钱的那一段，不是用户已有的数据。

## Consequences

- 升级到这个版本后，原本在跑的质量判断会立刻停。用户要在「配置 · 平台配置」里逐个平台打开，
  否则「重点关注」不再新增行 —— 页面空列表时会写明是哪个平台没开。
- 与 ADR-0015 的第 5 条是两层判据：自动回复关着时这个开关轮不到生效。两个条件都满足才会调模型。
- 读法不能沿用另外两个开关的「null 即开」：这一列读到 `null` 按关。抄错的表现是
  「一个从没配过的平台悄悄开始花钱」，既没有异常也没有日志。
