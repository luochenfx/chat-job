# 可视化只做概览页里的 7 日走势

## Status

accepted（2026-11-05），已实现（0.5.0）。落地位置：`RunStore.counterSeries` 读 7 日（`DailyCounterMapper`
保持空 mapper：它现在只用于插入，读走 `JdbcTemplate`，与 `deliveredToday` 同处）、`/api/system/overview`
在每张平台卡里多带一段 7 日序列（`series.days` + `points[]`，点里带 `offset`）、
`console/components/Sparkline.vue` 画线，由 `index.vue` 卡内的两条 sparkline 使用。

## Context

控制台六页里没有任何图形：`console/package.json` 只有 nuxt / vue / vue-router，全仓没有 canvas、
手绘 SVG 或图表依赖。要加图形，得先说清它回答什么问题。

三个事实把范围压窄了：

1. **`daily_counter` 是唯一按天存的表**（`platform + day` 唯一，只有 `delivered` 与 `evaluated`
   两列），但它现在只被读「今天」那一行（`RunStore.deliveredToday` / `evaluatedToday`）。全仓
   没有按天分桶的查询，也没有任何接口返回时间序列。
2. **能跨周比较的数据只剩它**：`run_log` 14 天、`reply_log` 90 天会被清；`delivery` 永久保留，
   但 `SKIPPED` 行会随岗位清理一起消失（`delivery` 的 FK 是 `ON DELETE CASCADE`）。
3. **文档里多处引用的「日报」从未实现**：`spec/0004`、`spec/0005`、`ADR-0004`、`ADR-0005` 里共
   八处把它当成既有产物来引用（「日报里的今日投递」「日报里看不到」），实际没有生成它的代码，
   `spec/0004` 的交付物清单里也没有。`CONTEXT.md` 里那一处已在本 ADR 落地时改成「界面上」。
   所以这次不是「补一个日报」，而是决定要不要产生独立的统计产物。

使用场景收窄成一条：每天启动投递前后扫 30 秒，看完只可能做两个动作——调配额、停某个平台。
周末复盘、运行时盯屏都不在这一版。

## Decision

1. **只读已有表，不建指标表、不新增采集。** 数据源就是 `daily_counter`。这与
   `spec/0006-humanized-interaction.md` 里「不建新的指标表或报表」是同一条约束，不是对它的推翻：
   那条拒绝的是新建统计表，这里一个表都没建。

2. **位置在概览页的平台卡内，不新增页面、不新增导航项。** 导航已有六项，而「7 个点 × 2 平台」
   的内容量撑不起一页；更重要的是，属于某个平台的数字不该提到全局层——`index.vue` 的注释里
   已经写死了反方向（与平台无关的四项才进全局条）。

3. **只做 7 日，不给 30 / 90 日选择器。** 真实历史是 boss 9 天（10-28 起）、zhaopin 6 天
   （10-31 起）。给一个永远填不满的控件，比不给更糟。

4. **画绝对数，两条独立小图，不算达成率。** `platform_config` 只存**当前**配额，没有历史：
   拿今天的 50 去除 10-28 的 0 次投递，得到的是伪精度。两个指标量纲差 3 倍（0–50 与 0–180），
   共用一条 Y 轴会把投递压成贴底的线。

5. **手写 SVG，不引图表库。** 控制台是 `nuxt generate` 的静态产物、直接打进 jar 分发，引库的
   体积会进安装包。而且现有色板只有 ok / warn / danger 三个语义色、没有序列色，无论用不用库
   都得先定义色板——库省不掉这一步。

6. **缺行不补 0。** `boss 10-31` 是「投了 0 个」（行存在、值为 0），`zhaopin 10-30` 是「没跑」
   （行不存在）。两者在折线上必须是「真实 0 点」与「断开」的区别，这和概览卡里「0 是真实发生的
   0，不拿 — 盖掉」是同一条原则。

7. **这一版不做转化率，也不做日志时间轴。** 转化率的瓶颈是样本与口径：`conversation` 43 段、
   `reply_log` 77 行，且「哪次投递对应哪段会话」只能靠 `job_posting_id` 反推（同一岗位可多次
   投递、值守发简历也建会话）。日志时间轴（每张岗位卡的耗时条带）是零成本的，但它回答的是
   「卡在哪张卡」，属于排障，不服务上面那两个动作，是独立功能。

8. **不前置前端架构重构。** `config.vue` 那 1314 行是表单字段，与图表没有复用关系；图表页
   在新文件里，不继承它的债。只顺手抽一个 `usePolledData()`（取数 + 轮询 + 空态），六页里已经
   共享的 `useApi` / `useToast` / `usePlatform` 不动。**必须先动的是后端**：全仓没有任何多天读取，
   `daily_counter` 至今只被读「今天」一行。

## Consequences

- 卡片高度各加约 24px，两条折线固定在「今天主动联系」「今天查看的岗位」两个数字下方。一个从没
  跑过的平台画成空槽位，不是一条贴在 0 上的直线——那会被读成「天天投 0 个」。
- 两个平台起点不同，前端按各自实际有的天数画，**不要补成 7 个对齐槽位**，否则 zhaopin 的
  10-28 到 10-30 会被读成「三天没投」。
- 图里只有一档语义色：最后一点到顶时用 `--warn`，其余用 `--muted`。不新增色变量，所以一张图
  不会出现第二档含义。
- `daily_counter` 目前没有任何清理路径，7 日视图会一直有数据；但它也没有备份或保护，手工删过
  就断了。要加清理时必须先决定趋势图认不认这段历史。
- 转化率与日志时间轴记在这里但未做。做之前要重估口径，不要照着这份 ADR 的第 7 条直接开工。
