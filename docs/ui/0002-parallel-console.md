# 多平台控制台界面规格（方案 B）

> 落地 [`spec/0004`](../spec/0004-zhaopin-parallel.md) 阶段 2c 的前端部分。
> 架构前提见 [`adr/0003`](../adr/0003-parallel-platforms.md)：每个平台一条独立流水线，并行运行。
> 本文以**当前代码**（核对日期 2026-10-31）为准，行号指向核对时的位置。

## 0. 范围

**做**：控制台五个页面在多平台下的信息结构、切换器位置与行为、状态与空态、需要的接口形状、实施顺序。

**不做**：

| 不做 | 原因 |
|---|---|
| 平台开关（启用/停用） | 阶段 3。`platform_config.enabled` 字段与接口已就绪，阶段 2 只读显示，不提供开关 |
| `ai_config` / `reply_rule` 增加平台维度 | 前者是单行表，后者唯一键不含 platform，改表属于另一个 spec。阶段 2 只标注作用域 |
| 任务页双栏并排 | 日志框会窄到不可读，且要维护两套轮询 + 两条 SSE |
| 合并日志流 | 界面上日志本来就按 `run_id` 取，天然分平台。真要加前缀改的是 `data/logs/chat-job.log`，`RunService.log()` 是唯一入口 |

## 1. 结论：概览并排，其余单平台切换

| 页面 | 形态 | 一句话理由 |
|---|---|---|
| 概览 | **并排**（每平台一张卡） | 唯一要回答「两个平台都还活着吗」的地方。ADR-0003 做并行的动机就是这个，界面上看不见等于没实现 |
| 任务 | 单平台详情 + 平台分段控件 | 日志要宽度，两个平台的日志并排都不可读 |
| 岗位 | 单平台明细 + 平台筛选（含「全部」） | 列表查询用途，跨平台对比有意义，靠表格里的平台列区分 |
| 配置 | 单平台，**切换器只在「平台配置」tab 内** | 四个 tab 只有一个按平台存储，整页切换会出现「切到智联，AI 配置一个字没变」 |
| 系统 | 无需切换，按平台分行 | 登录态、浏览器本来就是每平台一份 |

判据只有一句：**「并排」用在回答「整体还好吗」的地方，「切换」用在回答「这个平台怎么了」的地方。**

## 2. 三条全局规则

### 2.1 控件必须和它作用的对象同屏

不给全站加一个「当前平台」的全局切换器。它是本方案最容易踩的坑：控件在侧边栏固定位置，却只对部分页面/部分 tab 生效，用户切完发现没反应，会判断成「坏了」。

| 位置 | 控件形态 | 作用域 |
|---|---|---|
| 概览 | 无 | 并排，不存在「当前」 |
| 任务 | 页头右侧分段控件 | 整页 |
| 岗位 | 筛选栏下拉（`全部平台` + 各平台） | 整页 |
| 配置 | 仅「平台配置」tab 内分段控件 | 该 tab |
| 系统 | 无（按平台分行） | — |

四处复用同一个 `PlatformSwitch.vue`，保证观感一致。位置跟着语义走，不是跟着「统一感」走。

### 2.2 前端不猜平台，只问服务端

`usePlatform.ts:9-43` 现有的约束保留并扩展：从「问唯一平台」变成「问清单后选一个」。平台 slug 不允许出现在任何模板字面量里。

选中项写进 URL query（`?platform=zhaopin`），并记忆到 localStorage：

- 刷新、后退、分享链接都保持在同一平台
- 首次进入取 localStorage；没有则取清单第一个
- **不要**用「当前有活跃 run 的平台」当默认——那个值会随运行状态变化，导致页面内容自己跳

### 2.3 分母不聚合

配额、评估上限、值守时段、巡检间隔都是 `platform_config` 每平台一份（`uk_platform_config(platform)`、`uk_daily_counter(platform, day)`）。任何跨平台相加的数字都会被读成错的分母：「24/60」看起来像还剩 36，实际是两个平台各 18。

只有一个例外：概览页顶部允许出现「合计」字样，但必须同时能展开到单平台，且不与配额并列。

### 3.3 卡片内容规范

固定六行，顺序不变（**位置固定是快速扫视的前提**）：

1. 平台名 + 运行状态标签（复用 `runStatusView`，`composables/useRunStatus.ts`）
2. 今日主动投递 `当前 / 配额`
3. 值守发简历（**单独一行，不与主动投递合并**，ADR-0004）
4. 今日评估 `当前 / 上限`
5. 当前动作 + 距上次动作多久（复用 `task.vue:247-260` 的 `activityLine` 逻辑，抽成 composable）
6. 浏览器就绪 + 组合进度
7. 操作区：一个主按钮 + 「查看任务 →」链接

### 3.4 卡片排序固定

按平台清单顺序（`boss`、`zhaopin`）**固定排列**，不按状态、不按活跃度排。卡片会跳位置的话，人无法建立空间记忆，每次都要重读一遍平台名。

### 3.5 按钮规则

**一张卡同时只有一个操作按钮**，避免误点：

| 平台状态 | 按钮 | 说明 |
|---|---|---|
| 未启动 / 已结束 | 「启动」（primary） | 固定 NORMAL 模式；演练只在任务页选 |
| RUNNING / STANDBY | 「停止 {平台名}」（danger） | **必须二次确认**，确认文案含平台名 |
| WAITING_DUTY | 「取消等待」（danger） | 文案要区分「取消等待」与「停止」，同 `task.vue:19-21` |
| PAUSED | 「继续」（普通） | 暂停/继续留在任务页，卡片上不出现 |

按钮文案**一律带平台名**，不用裸的「停止」。这是本方案防反直觉最省事的一招。

### 3.6 空态

| 情形 | 显示 |
|---|---|
| 今日该平台没有 run | 计数照实显示 0，副标题写「今天还没有跑过」——**不要**用 `—` 盖掉。0 是真实发生的 0，`—` 留给「这一轮不可能产生该数字」（演练模式的已投递） |
| 平台未启用（阶段 3 预留） | 卡片仍在，整体降透明度 + 「已停用」标签，按钮禁用 |
| 只有 1 个平台 | 仍然是卡片形态，靠 `auto-fit` 铺满宽度，**不塌缩回老布局**。否则阶段 3 加开关时界面会跳变 |
| driver 不可用 | 全局条变红，每张卡的启动按钮禁用 + `title` 说明原因 |

## 4. 任务页

### 4.1 改动点

| 项 | 现状 | 改后 |
|---|---|---|
| 平台来源 | 无 | 页头右侧分段控件 + `?platform=` |
| `refresh()` | 固定 `/runs/current` | `/runs/current?platform=X`（`task.vue:336-354`） |
| 重置守卫 | 只在 `run.id` 变化时清 SSE/日志（`task.vue:343-349`） | **同时看平台**：平台变化 → `clear()`、`open(null)`、`logs=[]`、`lastLogId=0`、`currentRunId=null`、`run=null` |
| 按钮文案 | 「停止」「暂停」 | 「停止 BOSS 直聘」「暂停 BOSS 直聘」 |
| 无 run 空态 | 「还没有任务」 | 「BOSS 直聘 还没有任务记录」+ 启动按钮 |

### 4.2 必须补的守卫

现在 `currentRunId` 用了 `!==` 判断，同 id 不同平台不会触发重置。两个平台的 run id 不会重复，所以 id 变化本身够用——**但切换过程中会有一帧旧数据**：query 变了、请求还没回，此时 `run` 仍是上一平台的。

正确顺序：

```ts
// 平台变化时先清空，再发请求。不要等响应回来才切
watch(platformSlug, () => {
  clear()              // 断开 SSE
  run.value = null
  logs.value = []
  lastLogId = 0
  currentRunId = null
  combinations.value = []
  refresh()            // 用新平台拉
})
```

不发这一步的话，切到智联的瞬间会看到 BOSS 的日志，然后日志"消失"变空——比看到空白更让人困惑。

## 6. 配置页

### 6.1 tab 标注作用域

`config.vue:461-466` 的 tab 定义加后缀：

```
模型提供商 · 两平台共用
AI 配置 · 两平台共用
平台配置 · BOSS 直聘        ← 分段控件只在这个 tab 内
值守规则 · 两平台共用
```

后缀比任何说明文字都有效。用户在 AI 配置页看不到平台切换器，标题又说「两平台共用」，就不会去找开关。

### 6.2 平台配置 tab 内的切换

分段控件放在 `config.vue:293` 那个 `<section>` 顶部，与它作用的三张卡同屏。切换时：

1. 检查 dirty（见 6.3），有未保存改动先拦截
2. **重置到默认值再 assign**——`Object.assign(platform, c)` 是当前写法（`config.vue:618`），切到智联时 `salary`/`experience`/`degree` 等字段在响应里不存在，`Object.assign` 会留下 BOSS 的旧值。接着点保存，这些旧值就被写进智联的配置行。这是**数据污染**，不只是显示问题
3. 重新拉字典（`loadDictionary()`，`config.vue:626-638` 已按平台查）

```ts
function applyPlatform(c: any) {
  Object.assign(platform, DEFAULT_PLATFORM_CONFIG)  // 先回到默认
  Object.assign(platform, c || {})
}
```

`DEFAULT_PLATFORM_CONFIG` 取现在 `config.vue:542-565` 那个字面量。

### 6.3 未保存拦截

现在 `savePlatform()` 直接 PUT 整个 reactive 对象、不回读、不标记 dirty（`config.vue:789-799`）。切换平台时草稿被静默覆盖。

补三件事：

1. 加载后拍快照 `const snapshot = JSON.stringify(platform)`
2. `dirty = computed(() => JSON.stringify(platform) !== snapshot)`
3. 切 tab / 切平台前若 dirty → 弹确认「有未保存的平台配置改动，放弃并切换？」

顺带补**保存后回读**：`saveAi` 已经这么做了（`config.vue:781`），`savePlatform` 没做。后端对 `watchIntervalSeconds` 有 30–600 的钳制，不回读的话界面显示的是用户填的、库里存的是钳制后的。

### 6.4 黑名单卡

`config.vue:435-445` 的「黑名单」卡留在平台配置 tab 里会让人以为它按平台存。两个选择：

- 移到「值守规则」tab（语义更近：命中即不回）
- 留在原地，标题后加「· 两平台共用」

推荐后者（改动小），标题写全：`黑名单 · 两平台共用`。

## 7. 系统页

| 项 | 改动 | 落点 |
|---|---|---|
| 登录态 | 从一张卡改为**每平台一行**：平台名 / 已登录-未登录 / [探测] / [打开登录页] | `system.vue:59-73` |
| 探测/打开 | 加 `platform` 参数 | `system.vue:157-179` |

`browserReady` 同理：现在是 `session.isReady()` 单个布尔（`SystemController.java:86`）。2a 之后按平台各一份，界面上两个平台各一行。

## 8. 接口契约

### 8.1 新增

| 接口 | 返回 |
|---|---|
| `GET /api/system/platforms` | `[{platform, label, filters, note, enabled}]`，替代「只有一个平台」的语义 |
| `GET /api/system/overview` | `{global:{driverAvailable,driverMessage,browserChannel,dictionaryTotal,serverTime}, platforms:[{platform,label,enabled,run:{id,status,mode,currentAction,lastActivityAt,startedAt,combinationIndex,combinationTotal},delivered,quota,evaluated,evalLimit,resumeOnRequest,browserReady,loginState}]}` |

`overview` 是给概览页一次取全的。不让前端拼 `status` + N×`current` + N×`config`：那样四个请求之间状态不一致，卡片会显示自相矛盾的组合（run 已结束但计数还是上一轮）。

`/system/status` 保留：系统页仍需要 driver 详情（`driverDir`、`nodePath`）、自检、清理入口。它的 `deliveredToday` 等按装配平台计的字段保留一个版本，前端不再依赖。

### 8.2 加参数

| 接口 | 参数 | 缺省行为 |
|---|---|---|
| `POST /api/runs` | body 加 `platform` | 装配平台（向后兼容 `curl` 脚本） |
| `GET /api/runs/current` | `?platform=` | 装配平台 |
| `POST /api/system/probe-login` | `?platform=` | 装配平台 |
| `POST /api/system/open-login` | `?platform=` | 装配平台 |
| `GET /api/jobs` | `?platform=` | **全部平台**（与页面默认一致） |
| `GET /api/watcher/unread-tasks` | `?platform=` | 全部，`counts` 增加按平台分组 |

### 8.3 必须改路由

| 接口 | 现状 | 改后 |
|---|---|---|
| `POST /api/runs/{id}/pause\|resume\|cancel` | 忽略 `{id}`，直接调 `runService.pause()/stop()`（`RunController.java:51-67`） | 按 `{id}` 查出 `platform`，路由到该平台的 `RunService` 实例 |

这是**当前真实存在的 bug**：有两个平台之后，在 BOSS 的任务页点停止，会停掉智联那条。修法是让控制器相信路径参数，而不是相信「只有一个」。

### 8.4 依赖关系

`{id}` 路由依赖 2b 的 `RunService` registry；`/runs/current?platform=` 依赖 2b 的按平台实例化。所以 **2c 排在 2a/2b 之后**，不能提前。8.1 的只读接口可以提前做。

## 9. 实施顺序

四步，各自可编译、可回滚：

| 步 | 内容 | 验收 |
|---|---|---|
| 2c-1 | 后端只读：`/system/platforms`、`/system/overview`、`/jobs?platform=`、`/unread-tasks?platform=` | `curl` 能拿到两个平台的独立计数；不改任何写路径 |
| 2c-2 | 后端写路径：`POST /runs` 带 platform、`{id}/pause\|resume\|cancel` 按 id 路由、probe/open-login 带 platform | 造两条 run，停 A 不影响 B；`curl` 停错 id 返回 404 而不是误停 |
| 2c-3 | 前端骨架：`usePlatform` 改清单、新增 `PlatformSwitch.vue`、概览页改卡片 | 概览页不滚动就能同时看到两平台状态；卡片顺序固定 |
| 2c-4 | 前端其余四页：任务切平台与重置守卫、岗位平台列、配置作用域与 dirty 拦截、系统按平台分行 | 走完第 10 节的清单 |

2c-1/2c-2 是后端，可以并行于 2a/2b 的大部分；2c-3/2c-4 必须等 2a/2b 能真正跑起两个浏览器。

### 2c-1 实施记录（2026-10-31，真实库 + 空库两次启动取证）

四个接口按 §8 的形状落地，未碰任何写路径。落地时定下三处口径，都写进了代码注释：

| 决定 | 理由 | 证据 |
|---|---|---|
| 平台清单是常量 `PlatformInfo.KNOWN`，不查库 | 能跑哪些平台由「代码里有哪些适配器」决定。按 `platform_config` 的行推，一个从没跑过的平台会从界面上消失，人也就没有入口去第一次配置它 | 空库里 `platform_config` 是 0 行，`/system/platforms` 照样回两条 |
| `overview` 不返回 `loginState` | 探测登录态要读浏览器 cookie，会为了刷一次页面把浏览器拉起来，而概览每 5 秒轮询一次 | `api/system/overview` 全程未触发浏览器启动（启动日志无「浏览器已启动」） |
| 概览读配置走新增的 `ConfigStore.peekPlatformConfig()` | 原 `platformConfig()` 查不到就 insert 一行；轮询一个只读接口不该改库 | 空库实例调完 `/overview` 与 `/platforms` 后 `platform_config` 仍为 0 行 |

两处与 §8 契约的偏差，都是为了「2a/2b 之前也不能说谎」：

- **`browserReady` 按装配平台判定**：2a 之前一个进程只有一份 `BrowserSession`，未装配的平台返回 `false` 是事实而非占位。2a 之后改为问该平台自己的 session。
- **`counts.byPlatform` 不受 `platform` 筛选影响**：合计收窄到所选平台，明细永远描述整个窗口。切到智联时若把 BOSS 的 8 条显示成 0，那不是筛选结果而是错的数字。

空库启动下每张卡的 `run` 字段被 Jackson 的 `non_null` 省掉（没有 Run 记录），前端据此显示「今天还没有跑过」。

## 10. 反直觉检查清单（验收用）

1. 概览页**不滚动**就能同时看到两个平台的运行状态。
2. 任何操作按钮的文案都包含平台名，或紧跟在同一张卡/同一行内。
3. 切换平台后，日志、事件、组合队列**都不残留**上一个平台的内容（含切换瞬间的那一帧）。
4. 配置页只有「平台配置」tab 有切换器；其余三个 tab 标题带「两平台共用」。
5. 概览卡片位置不随运行状态变化。
6. 切平台后按 F5，仍停在同一平台（URL query）。
7. 配额分母永远来自单平台配置，界面上不出现「两平台合计配额」。
8. 「今日主动投递」与「值守发简历」不合并、不相加、不互相顶替。
9. 平台未启动时，计数显示真实的 0 并配「今天还没有跑过」，不用 `—` 掩盖。
10. driver 红灯（两平台都不能跑）与 browserReady 红灯（只影响一个）在视觉上可区分。

## 11. 风险

| 风险 | 处置 |
|---|---|
| 概览每 5 秒轮询 `overview`，后端每次要算 N 个平台的计数与浏览器状态 | 2 个平台可接受；`overview` 内不做 driver 探测（复用缓存），避免刷页面拉起浏览器 |
| `Object.assign` 残留上一平台字段，被写进新平台配置行 | 6.2 的「先重置再 assign」；补一条单测：切换后 PUT 的 body 不含对方平台独有字段 |
| 分段控件在四个位置，用户觉得不统一 | 四处复用同一组件、同一视觉权重；位置跟着作用域走是刻意的 |
| 阶段 3 加到第 3 个平台，概览网格换行 | `auto-fit` 已处理；第 3 个平台时卡片变窄，六行内容仍放得下（380px 起） |
| 平台切换后 SSE 重连延迟导致「未连接」闪烁 | 切换时先清空再连，标签短暂显示「未连接」是准确的，不要伪装成已连接 |
